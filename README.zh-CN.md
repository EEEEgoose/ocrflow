# OCRFlow 中文使用手册

[返回项目首页](README.md)

适用于 OCRFlow 1.4 系列、Zotero 10.0.*。插件默认不在导入文件后自动识别。

## 1. 配置服务

打开 Zotero 设置中的 **OCRFlow → 配置与同步**，先创建配置密码或导入加密配置，再配置准备使用的服务。配置支持加密保存、导入 / 导出及通过 Zotero 文件同步传输，详见[配置与同步指南](docs/CONFIGURATION-SYNC.zh-CN.md)。

### MinerU

支持官方云端 API v4 和本地 V1，两者分别保存地址、Token 和解析档位。

| 项目 | 示例或说明 |
| --- | --- |
| 官方云端地址 | `https://mineru.net/api/v4` |
| 本地服务根地址 | `http://127.0.0.1:41835`，填写实际服务地址，不追加 `/v1` |
| Token | 云端需要；本地服务按其要求填写，可支持免密 |
| 本地解析档位 | Flash、Basic、Standard、Advanced，取决于服务支持情况 |

本地服务返回页数或阶段时，任务队列显示实际进度；否则显示文件计数或任务状态。需要为 MinerU 4.0.10 增加页进度时，参见 [Marker 与 MinerU 本地页进度部署指南](docs/OCR-PROGRESS-DEPLOYMENT.zh-CN.md)。官方云端有进度字段时同样读取，不用计时器模拟百分比。

云端识别语言可选择：

- **自动**：读取原文件父条目的语言，如 `ar-SA` 映射为阿拉伯语、法语映射为拉丁文字。
- **手动选择**：指定语言包，不改写条目的语言字段。
- **使用云端默认值**：省略语言参数。

没有父条目、语言为空或无法识别时，自动模式省略语言参数。本地 V1、MarkItDown 和 AI OCR 不接收这一云端语言参数。

### PaddleOCR

可选择官方 API 或自部署 API，两种配置分别保存。

- 官方地址默认 `https://paddleocr.aistudio-app.com/api/v2/ocr`；填写 AI Studio 访问令牌及官方支持的模型名称。插件上传文件、查询任务并下载逐页结果；大 PDF 分批提交。
- 自部署填写完整文档解析服务的根地址，例如 `http://127.0.0.1:8080`。插件调用 `/layout-parsing`；令牌可留空。设置中的部署模型名称用于记录，实际模型由服务器部署决定。
- 单独的 VLM 推理服务不能代替完整文档解析接口。
- 两种方式都保留原始响应；能获取到的结构、页码和坐标随全文保存。

### 双引擎校勘

在设置中开启后，分别选择主识别 A 与对照 B。两个选择框允许 MinerU 本地 / 云端、PaddleOCR 官方 / 自部署、Marker 和已配置的 AI 视觉模型。开启时按 A 的选择生成底稿。

A 为 MinerU 时，B 不提供任何 MinerU 选项；A 为 PaddleOCR 时，B 不提供任何 PaddleOCR 选项。两个 AI 来源必须使用不同模型。Marker 与明确配置为同一 Surya OCR 模型的 AI 来源也不能互为双引擎。切换 A 导致 B 无效时，B 会清空，需重新选择并保存。

识别完成后，可右键全文 → **审阅 OCR 校勘**，查看原图、底稿和对照文字。启用 AI 辅助时，明确建议自动另存校勘版本；无法确定项保留底稿。未启用 AI 或需要进一步人工修正时，核对原图后确认并另存新版本。旧附件不被覆盖。若分块方式不同，窗口按结构差异提供相关文本块供手动修改。对照识别失败时，可以单独重试 B。

右键全文 → **查看整理差异** 查看恢复脚注、跨页合并及用户改字等记录。报告不把零差异当作 OCR 正确率证明。旧版全文没有结构与校勘文件，需要重新提取才能使用对应功能。

### Marker：自部署与 Datalab 在线

同一个 Marker 设置模块内选择“自部署 API”或“Datalab 在线 API”，两套连接信息分别保存。

- **自部署**：填写任务 API 根地址，如 `http://服务器地址:18501`。沿用真实页响应、整文件结果与服务端取消能力；部署见[统一进度指南](docs/OCR-PROGRESS-DEPLOYMENT.zh-CN.md)。
- **在线**：默认 `https://www.datalab.to/api/v1`，填写 Datalab API Key，选择 Fast / Balanced / Accurate。接入新的 Convert API，不使用已弃用的 Marker 在线接口。
- 连接测试不上传计费文档，只验证服务可达；密钥权限需由实际请求确认。
- 在线入口当前接收 PDF，整份上传一次，保留请求 ID 并轮询。云端未返回真实已完成页数时只显示处理状态，不模拟页进度；完成后保存 Markdown / HTML、图片、原始响应与可获得的页来源。
- 签名结果链接下载不向外部文件服务器发送 Datalab API Key。短暂断网和限流会重试查询，已有任务不重复上传。
- 在线“停止等待”只停止客户端查询，不能承诺取消云端执行；任务 ID 保留，可重新处理以继续查询。云端已失败的任务，明确重试时会提交一次替代请求。
- Marker 在线 / 自部署使用同一双引擎来源入口，不互相充当独立引擎；可与 MinerU、PaddleOCR 或其他视觉模型比较。

### MarkItDown

适合 EPUB、Office、HTML 等文档转 Markdown，也可提取 PDF 已有文字层。

可填写服务根地址或 MCP 地址，例如：

```text
http://127.0.0.1:33001
http://127.0.0.1:33001/mcp/
```

插件识别两类接口：

- REST：`/health` 与 multipart `/v1/convert`。
- MCP：协商连接，调用 `convert_to_markdown(uri)`，发送文件内容。

大 EPUB 和大 PDF 遇到请求体大小限制时会分批转换并按原顺序合并。单页仍超过服务限制时，任务会提示选择其他 OCR 方式。扫描 PDF 应使用 MinerU 或 AI 视觉 OCR。

### 服务商配置

最多保存 5 个服务商配置。每个配置包含共用的 API 地址和 Key，以及最多两个模型名称。

- API 地址填写服务的 Chat Completions 根地址，通常以 `/v1` 结尾。
- Key 按服务要求填写；本地免密服务可以留空。
- 模型名称按服务商提供的标识填写。AI OCR 需要支持图片输入，书目识别需要支持 JSON 对象输出。
- 编辑服务商配置不会改变各工作使用的模型。

每个模型分别设置：

| 设置 | 填法 |
| --- | --- |
| 上下文窗口 | 直接填写 `128K`、`1M`、`1.5M`，支持大小写；留空默认 `32K` |
| 最大输出长度 | 如 `8K`、`16K` 或整数 tokens；留空按工作默认分配，须小于上下文窗口 |
| 并发请求数 | 1–8 的整数；留空默认 1 |

1K＝1024 tokens，1M＝1024K；上下文最小 1K。原有绝对 token 数会等值显示为 K/M。上下文包括提示词、输入和预留输出；请按所用模型的能力填写。

两个模型各有“测试连接”和结果区域，可同时测试。测试使用当前填写内容，不自动保存。正常正文显示测试成功；仅有推理信息或输出截断时显示“已连通”及说明，表示尚未验证完整正文回复。真正的 API 错误仍显示具体原因。

从 1.3.6 起，总结等使用共享文档 AI 接口的请求最长等待 1200 秒，包含等待响应与读取完整回复；此前固定三分钟可能使慢响应的总结请求提前中止。连接测试仍使用短超时，且独立于 MinerU 的网络超时配置。正式请求超时会显示服务商与模型，可在队列重试；不自动重复提交整份总结请求。

修改模型名会清除该模型的旧测试；修改地址、Key 或切换服务商会清除相关结果并取消未结束的测试。

### 工作模型配置

建立父条目、补充信息、总结、AI OCR、翻译和阅读器大纲分别选择模型，也可“跟随默认模型”。选项显示“配置名称 + 模型名称”。总结语言、翻译格式 / 模式 / 目标语言 / 分段 / 重试，以及大纲开关均归入对应工作。

各工作显示当前提示词，并提供只读的内置提示词参考与“恢复内置提示词”按钮。可直接修改后保存；清空并保存或恢复内置提示词后保存，则跟随插件内置版本更新。已有自定义提示词会保留。总结和翻译支持 `{{language}}` 引用所选语言。

自定义提示词替换可编辑的任务说明；书目工作的固定 JSON 字段格式单独显示，仍会追加。总结分段、翻译分段和图片文字分片也会追加对应的处理要求。请求参数 JSON 留空使用默认配置。总结默认输出上限提高为 8192 tokens，仍受模型上下文预算限制；若显式设置输出参数，则优先使用该值。

上下文、最大输出长度和并发统一读取所选模型的设置。输出长度优先级为：工作请求参数 JSON 中的 `max_completion_tokens` / `max_tokens` → 模型最大输出长度 → 工作默认值。更大的输出预算会减少每段可容纳的输入；修改后保存，新任务或队列重试读取新值。旧工作级数值不再生效。请求参数中的模型、消息等保留字段不能覆盖。

服务商区“保存”仅保存当前服务商；页尾“保存”保存全部设置。切换服务商或 MinerU 接口类型时会保存该区当前内容，其他区未保存的编辑继续保留。

## 2. 执行工作

### 一键整理

选中文件附件或父条目，右键 **OCRFlow → 一键整理**。可批量选择，任务按文档依次处理：

1. **识别文档**：复用已有全文；没有时按设置识别。
2. **建立条目**：从全文建立父条目并挂载文件；已有父条目时跳过。
3. **补全条目**：补充缺失字段与人员角色，保留已有非空信息。
4. **生成大纲**：为关联 PDF 生成大纲；非 PDF 跳过。
5. **总结文献**：保存学术总结笔记。
6. **翻译文献**：按自然段翻译，使用已保存的语言、双栏对照与输出设置。

一键整理接受 Zotero 中的文件附件，不以扩展名白名单限制入口。TXT / Markdown / CSV 直接读取；PDF、PNG、JPEG 按当前解析设置处理；其他格式交给 MarkItDown，实际支持范围由已配置的服务决定。转换器不支持时，队列显示该服务的错误，不会把文件名当作全文建立书目。

同一父条目有多份原文件时，需要直接选择目标文件；同时选中父条目和目标文件只处理该文件。缺少附件或文件尚未下载到本机时显示“待补充”，补齐后点击“继续整理”。插件不查找或下载全文附件。

每份文档在队列显示一行。当前会话内重复点击会复用该行，已提取的全文和已完成的书目步骤不重复执行；识别或保存失败可以重试，重试读取最新设置。保留服务端解析任务时，继续使用原接口与解析方式。队列记录仍只保存于本次 Zotero 会话，清除记录或重启后不保留书目步骤的完成标记，已保存的全文仍可复用。

一键整理由用户手动启动，固定执行上述全流程，不受单独识别时的“自动生成大纲”开关影响。大纲或总结失败会记录错误并继续后续工作，重试只补跑未完成步骤；识别或建立条目失败会停止依赖步骤。总结、翻译也可单独执行。

### 建立父条目

选中没有父条目的原文件，右键 **OCRFlow → 建立父条目**。

只将文件名发送给 AI，不发送正文，不启动 OCR。生成初步书目条目后，挂载原文件及其已关联的全文附件。文件名没有明确给出的信息可以留空。

### 识别文档

右键原文件 → **OCRFlow → 识别文档**，选择：

- 使用设置中的服务
- MinerU（本地服务）
- MinerU（官方云端）
- MarkItDown
- PaddleOCR（官方 API）
- PaddleOCR（自部署 API）
- Marker（在线 / 自部署，仅 PDF）
- AI 视觉 OCR

本次选择不改动默认服务。重试保留服务选择，并读取其最新保存的配置。

MinerU 与 AI OCR 适用于 PDF、PNG、JPEG。AI OCR 将 PDF 逐页渲染成图片后发送给视觉模型；图片文件直接发送。EPUB、DOCX、PPTX、XLSX、HTML 等使用 MarkItDown，TXT/Markdown/CSV 直接读取。

全文始终保留 Markdown。PDF 和图片可勾选“同时生成 HTML”，此时保存 HTML 主附件及配套 Markdown。EPUB 等文档保存 Markdown。

### 补全条目

需要已有父条目和与文档关联的 Markdown。选择原文件、全文附件或其父条目后执行。

AI 读取全文提取类型、题名、人员、出版信息和标识符。新证据可以修正现有字段；空结果不会清空已有内容。长文分段识别，前部出版页的信息优先。

非中文文献保留原文 `title`，将完整题名的中文译名写入 Zotero `shortTitle`（短标题）字段；原文 `language` 保留。中文文献不额外翻译题名。此书名翻译使用补充信息工作所选的模型。

### 总结文献

读取对应 Markdown，按研究问题、材料与方法、主要论证或发现、结论与贡献生成学术总结，保存为父条目下的笔记。

长文先分段整理再汇总。同一文档再次总结会更新对应的 OCRFlow 总结笔记。

### 翻译文献

选择含可翻译 Markdown 的父条目或全文附件。可以设置目标语言、分段字符数、自动重试次数和保存格式；上下文和并发使用翻译工作所选模型的设置。

输出可为 Markdown、HTML 或原文译文双栏 HTML。1.0 的双栏逐自然段对齐，多个段落仍可合成一次请求；译文按段落 ID 回填，失败或漏译不会挤占下一段。代码、公式、脚注引用和本地图片受保护，图片数据不作为翻译文本发送。

翻译不会把物理页当作自然段。已有跨页结构继续保留；页码标记前后被空行隔开的未完正文，会先接回同一段再翻译。完整段落和标题、列表、脚注等结构边界继续保留；没有连续页码依据时不自动拼段。跨页段落仍只输出一组原文 / 译文对照，并显示全部来源页码（如“PDF 第 1、2 页”），原始全文文件不改写。

任务队列保留已完成译段。部分段落失败时可选择重试、放弃或保存部分译文；部分保存会标明未翻译内容。更改目标语言、分段或上下文预算后可能需要重新分段。

### 阅读器大纲

- **生成大纲**：优先利用 PDF 和解析结果中的结构，可使用默认 AI 模型生成目录和章节摘要。

解析后自动生成大纲默认关闭，可在设置中主动开启。

### AI 辅助校勘

在 OCRFlow 设置 → 双引擎校勘中，选择 A / B 来源后勾选“启用 AI 辅助校勘”，并单独选择一个支持图片的模型。模型连接、上下文、输出长度等沿用 AI 服务商中的配置。

流程为 A 底稿 → B 独立识别 → 程序比较 → AI 结合原图逐项复核 → 自动采用明确建议并另存校勘版本。底稿、两套识别结果、建议、原始 AI 回复和差异记录保留；无法确定或会丢失图片、脚注、公式引用的建议保留 A，列为待核对。

打开“审阅 OCR 校勘”可查看已自动采用的建议并进一步人工修正；人工修改需核对原图。AI 失败后可单独重试，明确建议直接另存新版本，不会重跑两套识别，也不会清空尚未保存的人工编辑。AI 服务失败时仍保留 A/B 结果供人工审阅。AI 复核会把相应原图和分歧文字发送给所选模型服务。

校勘窗口会显示原图加载进度，同页分歧复用已加载原图。原图加载失败或超过 30 秒时，可点击“重试原图”，保留正在编辑的文字；也可先在 Zotero 中打开原始文件，再返回重试。

校勘窗口采用不透明背景，原图与校勘内容分别滚动，顶部导航和底部确认区保持可见。窄窗口改为上下布局；全文和编辑框根据内容自动选择文字方向，便于核对阿拉伯文等文献。

## 3. 任务队列与保存

主界面右侧 OCRFlow 采用“文献操作与任务进度同页”。选中文献后，可一键整理、提取全文、补全条目、总结、翻译或生成大纲；需要父条目和全文的操作会在条件满足后启用。包含多份原文件时，先选择本次处理的附件，操作与任务记录只针对该文件。选择条目不会自动启动任务。点击操作后显示启动反馈；配置或识别失败的原因会直接显示在操作区。

选中子笔记时，操作针对所属文献，不读取当前笔记正文；独立笔记暂不支持文献处理。普通 `.md` / `.markdown` 附件也可作为全文用于总结、翻译和信息补全，需要已有父条目。一键整理优先复用明确选中的全文版本。没有关联原文件时不能重新 OCR，有原始 PDF 时才能生成大纲；重新 OCR 保留已有全文。OCR HTML 需要附件目录中的配套 MD，缺失时会提示恢复文件或选择原文重新识别。

“服务与模型设置”打开已有配置；任务使用已保存的识别服务、各项工作模型和提示词。任务开始时显示智能体式步骤流：完成步骤折叠、当前步骤展开服务和实际进度、后续步骤列为待执行；终止或失败后不再显示正在执行。手动收起后任务继续运行，图标保留任务数量。切换原生图标可返回条目详情。

面板支持终止和失败重试，完成后可查看结果、整理差异报告或审阅 OCR 校勘。对照识别失败时保留底稿，在校勘审阅窗口单独重试 B。逐段翻译失败时，可在侧栏补译失败段落、保存部分译文或放弃；部分译文不会显示为完整完成。底部“全部任务队列”进入设置中的完整列表。

翻译会分别显示读取来源、插图处理、请求模型和限流等待。遇到 HTTP 429 时优先遵守服务端的 Retry-After，未提供时按 30 秒、60 秒等间隔递增等待；自动重试仍被限流时暂停后续批次，并显示具体错误。可保存新的模型或请求参数后点击“重试失败段落”，已完成译段继续保留；没有完整译段时不能保存部分译文。连接测试的简短回复成功不代表长文翻译请求一定可完成。

OCRFlow 设置使用顶部七类标签：提取服务、AI 服务商、工作配置、双引擎校勘、输出保存、任务队列、配置与同步。提取服务按 MinerU、PaddleOCR、Marker、MarkItDown 与 AI 视觉分组；PaddleOCR 只显示一个默认入口，在配置中选择官方或自部署 API，两套连接信息分别保留。按钮点击有按压反馈，异步测试显示转动标识和忙碌文案，保存显示成功或错误状态。MinerU 的单次网络请求默认等待 1200 秒；已有明确保存的超时值继续生效。

“任务信息”可展开查看服务端任务 ID；进度刷新会保留展开状态。Marker 状态查询和结果下载短暂断网时自动重连三次，继续使用原任务；持续中断后可点“继续等待”，无需重新上传。旧版在短暂断网后可能显示失败，可在原会话点击“重新处理”查询原任务。

OCR、书目、总结、翻译和大纲共用队列，可查看进度和完整错误、重试、终止或清除已结束记录。文字可拖选后用 ⌘C / Ctrl+C 复制，每行另有“复制”按钮。

- 不同文献的不同操作、服务或模型可并行执行，运行期间新提交的独立任务立即调度；同一文献的冲突操作继续等待。
- 同一 AI 操作可按所选模型并发数同时处理多篇文献，多个操作的请求共享该模型的并发名额，避免并发叠加超限。不同模型独立计数。
- 同一 OCR 操作及服务通道按顺序提交；Marker / MinerU 自身的服务器排队和 GPU 限制仍由服务端决定，插件并行调度不等于服务端无限并发。
- 任务列表位于 OCRFlow 设置的“任务队列”标签，支持实时进度、重试、终止、复制和清除；离开设置后任务继续运行。
- 队列和未完成译段缓存仅保留在当前 Zotero 会话中。
- 终止自部署 Marker 或本地 V1 任务时请求服务端取消；Datalab 在线只停止等待；云端 / 通用 AI 的已发送请求可能继续运行。Marker 取消只针对当前任务 ID，不取消同一文件的其他提交，也不关闭共享模型服务。显示“取消未确认”时需继续检查，不能视为已终止后台任务。保存阶段不能中断。
- 入队任务使用设置快照；重试读取最新保存的配置。

“关联原文件与全文附件”默认启用，也可关闭。关联使用 Zotero 相关项，重命名不改变关联。关闭只影响新结果，不删除已有相关项。

同一文档重新提取全文会保留旧结果，后续默认使用最新关联结果。多文档没有关联时，请直接选择目标 Markdown。

## 4. 排错

更新插件前建议等待当前任务结束。队列与任务 ID 仅保留在当前 Zotero 会话；服务端任务独立保存，重启客户端不会自动取消它。


| 情况 | 处理 |
| --- | --- |
| 缺少父条目或 Markdown | 先执行对应步骤；插件不会自动启动其他服务 |
| Marker 一直排队 | 检查同一服务器前面的任务；模型吞吐日志可能属于另一份文档，按任务 ID 查询 |
| Marker 网络中断 | 等待自动重连，持续中断时点“继续等待”；勿为同一文档反复提交新任务 |
| Marker 0/N 页 | 区分排队、模型加载、版面和文字层分析；查看当前阶段，正文识别开始后才有页响应进度 |
| Marker 取消未确认 | 检查网络与任务 ID，重试终止；取消一条重复提交不会停止其他任务 ID |
| MarkItDown 404 | 核对地址及服务类型；MCP 服务不一定提供 REST `/health` |
| MarkItDown 413 | 等待分批转换；单页仍过大时改用 MinerU 或 AI |
| 扫描 PDF 无文字 | 使用 MinerU 或 AI OCR，MarkItDown 主要提取已有文字层 |
| 找不到原始 Markdown | 检查全文附件的本地文件；旧长文件名优先读取同目录中唯一的 Markdown，有多个候选时不猜测 |
| AI 测试仅显示“已连通” | 查看推理或截断说明；这不代表已验证完整正文回复 |
| AI 输出被截断 | 先提高所选模型的最大输出长度，例如设为 `16K`；若工作请求参数显式指定了 `max_tokens` 或 `max_completion_tokens`，需同步提高该值；确认模型支持且上下文足够，保存后从队列重试。推理模型可能同时消耗推理和正文额度，也可缩短要求的输出 |
| 上下文格式报错 | 使用 `128K`、`1M` 等带后缀格式，最小 1K |

提交问题时附上 Zotero / 插件版本、操作步骤、服务类型和队列错误。请先移除 Key、个人文件内容和本机路径。

接口返回格式参考：[OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[SiliconFlow](https://docs.siliconflow.cn/docs/userguide/capabilities/reasoning)。
