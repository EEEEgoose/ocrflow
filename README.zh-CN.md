# OCRFlow 中文使用手册

[返回项目首页](README.md)

适用于 OCRFlow 0.2.17、Zotero 10.0.*。插件默认不在导入文件后自动识别。

## 1. 配置服务

打开 Zotero 设置中的 **OCRFlow**。只需配置准备使用的服务。

### MinerU

支持官方云端 API v4 和本地 V1，两者分别保存地址、Token 和解析档位。

| 项目 | 示例或说明 |
| --- | --- |
| 官方云端地址 | `https://mineru.net/api/v4` |
| 本地服务根地址 | `http://127.0.0.1:41835`，填写实际服务地址，不追加 `/v1` |
| Token | 云端需要；本地服务按其要求填写，可支持免密 |
| 本地解析档位 | Flash、Basic、Standard、Advanced，取决于服务支持情况 |

本地服务返回页数或阶段时，任务队列显示实际进度；否则显示文件计数或任务状态。需要为 MinerU 4.0.10 增加页进度时，参见首页的 [本地 MinerU 页进度补丁部署](README.md#本地-mineru-页进度补丁部署)。官方云端有进度字段时同样读取，不用计时器模拟百分比。

云端识别语言可选择：

- **自动**：读取原文件父条目的语言，如 `ar-SA` 映射为阿拉伯语、法语映射为拉丁文字。
- **手动选择**：指定语言包，不改写条目的语言字段。
- **使用云端默认值**：省略语言参数。

没有父条目、语言为空或无法识别时，自动模式省略语言参数。本地 V1、MarkItDown 和 AI OCR 不接收这一云端语言参数。

### MarkItDown

适合 EPUB、Office、HTML 等文档转 Markdown，也可提取 PDF 已有文字层。

可填写服务根地址或 MCP 地址，例如：

```text
http://127.0.0.1:33001
http://127.0.0.1:33001/mcp/
```

插件识别两类接口：

- REST：`/health` 与 multipart `/v1/convert`。
- MCP：协商连接，调用 `convert_to_markdown(uri)`，发送文件内容。

大 EPUB 和大 PDF 遇到请求体大小限制时会分批转换并按原顺序合并。单页仍超过服务限制时，任务会提示选择其他 OCR 方式。扫描 PDF 应使用 MinerU 或 AI 视觉 OCR。

### 服务商配置

最多保存 5 个服务商配置。每个配置包含共用的 API 地址和 Key，以及最多两个模型名称。

- API 地址填写服务的 Chat Completions 根地址，通常以 `/v1` 结尾。
- Key 按服务要求填写；本地免密服务可以留空。
- 模型名称按服务商提供的标识填写。AI OCR 需要支持图片输入，书目识别需要支持 JSON 对象输出。
- 编辑服务商配置不会改变各工作使用的模型。

每个模型分别设置：

| 设置 | 填法 |
| --- | --- |
| 上下文窗口 | 直接填写 `128K`、`1M`、`1.5M`，支持大小写；留空默认 `32K` |
| 最大输出长度 | 如 `8K`、`16K` 或整数 tokens；留空按工作默认分配，须小于上下文窗口 |
| 并发请求数 | 1–8 的整数；留空默认 1 |

1K＝1024 tokens，1M＝1024K；上下文最小 1K。原有绝对 token 数会等值显示为 K/M。上下文包括提示词、输入和预留输出；请按所用模型的能力填写。

两个模型各有“测试连接”和结果区域，可同时测试。测试使用当前填写内容，不自动保存。正常正文显示测试成功；仅有推理信息或输出截断时显示“已连通”及说明，表示尚未验证完整正文回复。真正的 API 错误仍显示具体原因。

修改模型名会清除该模型的旧测试；修改地址、Key 或切换服务商会清除相关结果并取消未结束的测试。

### 工作模型配置

建立父条目、补充信息、总结、AI OCR、翻译和阅读器大纲分别选择模型，也可“跟随默认模型”。选项显示“配置名称 + 模型名称”。总结语言、翻译格式 / 模式 / 目标语言 / 分段 / 重试，以及大纲开关均归入对应工作。

各工作显示当前提示词，并提供只读的内置提示词参考与“恢复内置提示词”按钮。可直接修改后保存；清空并保存或恢复内置提示词后保存，则跟随插件内置版本更新。已有自定义提示词会保留。总结和翻译支持 `{{language}}` 引用所选语言。

自定义提示词替换可编辑的任务说明；书目工作的固定 JSON 字段格式单独显示，仍会追加。总结分段、翻译分段和图片文字分片也会追加对应的处理要求。请求参数 JSON 留空使用默认配置。总结默认输出上限提高为 8192 tokens，仍受模型上下文预算限制；若显式设置输出参数，则优先使用该值。

上下文、最大输出长度和并发统一读取所选模型的设置。输出长度优先级为：工作请求参数 JSON 中的 `max_completion_tokens` / `max_tokens` → 模型最大输出长度 → 工作默认值。更大的输出预算会减少每段可容纳的输入；修改后保存，新任务或队列重试读取新值。旧工作级数值不再生效。请求参数中的模型、消息等保留字段不能覆盖。

服务商区“保存”仅保存当前服务商；页尾“保存”保存全部设置。切换服务商或 MinerU 接口类型时会保存该区当前内容，其他区未保存的编辑继续保留。

## 2. 执行工作

### 建立父条目

选中没有父条目的原文件，右键 **OCRFlow → 建立父条目**。

只将文件名发送给 AI，不发送正文，不启动 OCR。生成初步书目条目后，挂载原文件及其已关联的全文附件。文件名没有明确给出的信息可以留空。

### 建立文本 OCR / 转为 Markdown

右键原文件 → **OCRFlow → 建立文本 OCR / 转为 Markdown**，选择：

- 使用设置中的服务
- MinerU（本地服务）
- MinerU（官方云端）
- MarkItDown
- AI 视觉 OCR

本次选择不改动默认服务。重试保留服务选择，并读取其最新保存的配置。

MinerU 与 AI OCR 适用于 PDF、PNG、JPEG。AI OCR 将 PDF 逐页渲染成图片后发送给视觉模型；图片文件直接发送。EPUB、DOCX、PPTX、XLSX、HTML 等使用 MarkItDown，TXT/Markdown/CSV 直接读取。

全文始终保留 Markdown。PDF 和图片可勾选“同时生成 HTML”，此时保存 HTML 主附件及配套 Markdown。EPUB 等文档保存 Markdown。

### 补充父条目信息

需要已有父条目和与文档关联的 Markdown。选择原文件、全文附件或其父条目后执行。

AI 读取全文提取类型、题名、人员、出版信息和标识符。新证据可以修正现有字段；空结果不会清空已有内容。长文分段识别，前部出版页的信息优先。

非中文文献保留原文 `title`，将完整题名的中文译名写入 Zotero `shortTitle`（短标题）字段；原文 `language` 保留。中文文献不额外翻译题名。此书名翻译使用补充信息工作所选的模型。

### 总结文档

读取对应 Markdown，按研究问题、材料与方法、主要论证或发现、结论与贡献生成学术总结，保存为父条目下的笔记。

长文先分段整理再汇总。同一文档再次总结会更新对应的 OCRFlow 总结笔记。

### 翻译文档

选择含可翻译 Markdown 的父条目或全文附件。可以设置目标语言、分段字符数、自动重试次数和保存格式；上下文和并发使用翻译工作所选模型的设置。

输出可为 Markdown、HTML 或原文译文双栏 HTML。翻译保留 Markdown 结构和本地图片，图片数据不作为翻译文本发送。

任务队列保留已完成译段。部分段落失败时可选择重试、放弃或保存部分译文；部分保存会标明未翻译内容。更改目标语言、分段或上下文预算后可能需要重新分段。

### 阅读器大纲

- **生成阅读器大纲**：优先利用 PDF 和解析结果中的结构，可使用默认 AI 模型生成目录和章节摘要。

解析后自动生成大纲默认关闭，可在设置中主动开启。

## 3. 任务队列与保存

OCR、书目、总结、翻译和大纲共用队列，可查看进度和完整错误、重试、终止或清除已结束记录。文字可拖选后用 ⌘C / Ctrl+C 复制，每行另有“复制”按钮。

- 文档依次处理；内部的分段或页面按模型并发设置处理。同一模型的父条目可批量建立。
- 关闭队列窗口后任务继续运行，可从设置页重新打开。
- 队列和未完成译段缓存仅保留在当前 Zotero 会话中。
- 终止本地 V1 任务时会请求服务端取消；云端任务停止客户端后续处理。保存阶段不能中断。
- 入队任务使用设置快照；重试读取最新保存的配置。

“关联原文件与全文附件”默认启用，也可关闭。关联使用 Zotero 相关项，重命名不改变关联。关闭只影响新结果，不删除已有相关项。

同一文档重新提取全文会保留旧结果，后续默认使用最新关联结果。多文档没有关联时，请直接选择目标 Markdown。

## 4. 排错

| 情况 | 处理 |
| --- | --- |
| 缺少父条目或 Markdown | 先执行对应步骤；插件不会自动启动其他服务 |
| MarkItDown 404 | 核对地址及服务类型；MCP 服务不一定提供 REST `/health` |
| MarkItDown 413 | 等待分批转换；单页仍过大时改用 MinerU 或 AI |
| 扫描 PDF 无文字 | 使用 MinerU 或 AI OCR，MarkItDown 主要提取已有文字层 |
| 找不到原始 Markdown | 检查全文附件的本地文件；旧长文件名优先读取同目录中唯一的 Markdown，有多个候选时不猜测 |
| AI 测试仅显示“已连通” | 查看推理或截断说明；这不代表已验证完整正文回复 |
| AI 输出被截断 | 先提高所选模型的最大输出长度，例如设为 `16K`；若工作请求参数显式指定了 `max_tokens` 或 `max_completion_tokens`，需同步提高该值；确认模型支持且上下文足够，保存后从队列重试。推理模型可能同时消耗推理和正文额度，也可缩短要求的输出 |
| 上下文格式报错 | 使用 `128K`、`1M` 等带后缀格式，最小 1K |

提交问题时附上 Zotero / 插件版本、操作步骤、服务类型和队列错误。请先移除 Key、个人文件内容和本机路径。

接口返回格式参考：[OpenRouter](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)、[SiliconFlow](https://docs.siliconflow.cn/docs/userguide/capabilities/reasoning)。
