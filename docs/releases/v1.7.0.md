# OCRFlow v1.7.0

## Agent 接入（MCP）

- 设置新增“Agent 接入”页。开启后，插件在 Zotero 本机 HTTP 服务上提供 MCP 接口 `http://127.0.0.1:23119/ocrflow/mcp`（端口随 Zotero 设置），只监听本机。默认关闭；开启时生成 48 位访问令牌，请求需带 `Authorization: Bearer <令牌>`。令牌只保存在加密配置中，可随时重新生成，原令牌立即失效。
- 提供四个工具：`ocrflow_run` 对条目执行一键整理、识别（可指定识别服务）、建立父条目、补全书目、总结、翻译、标题翻译和大纲，支持只预览不执行；`ocrflow_tasks` 查看任务状态；`ocrflow_cancel` 终止任务；`ocrflow_get_result` 分段读取识别全文、译文和总结。任务提交后立即返回任务号，不等待完成；相同任务已在队列中时不重复创建。
- 任务和结果分别标明文件附件（`attachment`）、父条目（`parent`）和结果条目（`resultItem`），便于 agent 对应。
- 同时支持 MCP 2026-07-28 无状态协议，以及 2025-11-25、2025-06-18、2025-03-26、2024-11-05 的初始化握手。
- 设置页可按客户端复制接入配置：Claude Code 命令、Codex `config.toml`、Gemini CLI `settings.json`、通用远程 MCP 配置（Cherry Studio、Cline、Cursor 等，可搭配 DeepSeek 等模型），以及只能启动本地命令的客户端使用的 mcp-remote 配置。
- 配置未解锁时接口返回 503 并提示解锁；建议在配置页勾选“记住解锁”，重启 Zotero 后 agent 可直接使用。

## 同语种不翻译

- 原文已是所选目标语言时不再翻译，也不生成译文附件，任务显示“原文已是 X，无需翻译”；一键整理中的翻译步骤标为“已跳过”。语种判断不确定（文字太少或多语混排）时照常翻译。

## 验证

插件自动化测试全部通过。在独立的 Zotero 10.0.9 实例中实测接口的认证、协议握手、任务提交、终止和结果读取，并用 Claude Code 完成“识别 → 查询 → 读取全文”流程。Codex、Gemini CLI 和 mcp-remote 未实测。
