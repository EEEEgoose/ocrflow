# OCRFlow v1.6.6

## 自部署 MinerU 4 恢复页码

- 自部署 MinerU 4 返回的 `middle_json` 改为新格式（`schema: docvortex.middle`，版本 2.0）：页面放在 `pages` 中，坐标为相对页面的比例，没有旧格式的 `pdf_info`。此前插件只识别 `pdf_info`，找不到时只能使用 MinerU 的整篇 Markdown，结果没有页码，也缺少页眉页脚整理、脚注整理和原版式 HTML 所需的位置数据。
- 新增 `OCRFlowDocument.mineruLayoutPayload()`：旧格式原样返回，新格式按每页尺寸把坐标换算为点，并转换为 `pdf_info` 结构，再交给原有的 MinerU 处理流程。页眉、页脚、页码、页脚注和页边文字的归类与在线 MinerU 一致；图表按图片处理，代码块保留 `guess_lang` 语言标记。
- 新格式用 `continues_prev` 标明“接续上一段”。跨页接续沿用原有接段逻辑，同一页内被拆开的段落也会接上，整理差异中记为“页内接段”。
- 在线 MinerU 仍为旧格式，不受影响。

## 重建页码

- 任务侧栏“更多操作”新增“重建页码”。对没有页码、但保存了 MinerU 原始数据的全文，读取 `_ocrflow/raw/engine-a` 中的 `middle_json`，生成带页码的新附件，不调用识别服务，原附件保留不变。新附件沿用原附件的布局（原文布局或 MD 布局）。
- 图片按 MinerU Markdown 中首次出现的顺序，对应到已保存的 `image-1`、`image-2`……。已有页码、缺少原始数据或图片数量不一致时直接提示原因，不生成附件。

## 页码显示

- 识别结果的 Markdown 和普通 HTML 在每页开头显示“原文第 N 页”。保留原版式的 HTML 在每页上方显示同样的页码，打印时页码与该页不分开。
- 双语 HTML 的页码行改为“原文第 N 页”，跨页段落的来源提示改为“来源原文第 N 页”。
- 翻译前去除显示用页码时，同时识别旧版的“PDF 第 N 页”，旧文件照常翻译。

## 跨页接段

- 页边文字保留显示，但判断段落能否接上时不再作为上一段。此前页边文字位于上一页末尾时会阻断接段。
- 识别服务明确标明接续时，段落可越过相邻两页之间的图片、图注和表格接上，图表排在接好的段落之后。两部分之间隔着整页时仍不接段，以保持页码标记顺序。

## Marker 提交阶段的终止

- 此前在进度显示“提交 Marker 任务”时终止，任务会被标为“取消未确认”。这时插件可能还没开始上传，但没有任务 ID 时“重试终止”无法成功，任务也不能从队列清除。
- 新增步骤编号 `uploading`（请求发出前记录）和 `rejected`（服务端返回错误）。尚未上传时直接终止；服务端返回错误时确认未建立任务。
- 上传时插件生成 32 位十六进制任务 ID，随表单字段 `job_id` 提交，并写入恢复记录。上传响应丢失时按此 ID 取消；服务端返回 404 且其接口声明支持 `job_id` 时，确认未收到完整文件、未创建任务；服务端无法连接时可重试终止。
- 无法确认时（旧版服务端，或更新前已卡住的任务）任务结束并提示到服务端检查，不再要求反复重试。Datalab 在提交阶段终止也不再卡住。
- 停在 `uploading` 的任务恢复后暂停，与 `submitting` 相同，避免重复上传。
- 服务端 `server/marker_jobs.py` 接受可选的 `job_id`：格式无效返回 400，已存在返回 409。需重新部署服务端，按任务 ID 取消才会生效；未更新时插件仍可使用。

## 验证

443 项插件测试和 11 项服务端测试通过。新增测试覆盖：新格式的分页、结构、坐标与接段；按原始数据重建页码及三种拒绝情况；页边文字和相邻页图表处的接段，以及隔整页不接段；Marker 在上传前、上传中、服务端拒绝、响应丢失、服务端不可达和旧版卡住任务的终止；`uploading` 任务的恢复暂停。

开发期间用本机 68 份自部署 MinerU 4 结果离线验证：全部能重建，页码数等于页数且顺序正确，图片均对应到已有文件，正文与 MinerU 自己的 Markdown 对照覆盖 98.8%–100%。MinerU 标明的跨页接续中，未接上的从 394 处降到 2 处（前面是代码块）。新功能和 Marker 终止尚未在真实 Zotero 和 Marker 服务上验证。
