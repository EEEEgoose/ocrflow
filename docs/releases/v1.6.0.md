# OCRFlow v1.6.0

## 任务持久化与恢复

- 新增 `task-recovery.js`，在 Zotero 数据目录的 `ocrflow-tasks/queue.enc` 中保存加密恢复记录。记录使用 AES-GCM 加密，密钥保存在本机安全凭据存储中。
- 新任务入队后立即保存，执行前完成检查点写入。其余队列状态每 5 秒合并保存。云端批次申请、上传成功、任务 ID 回执、译段完成和结果保存等关键节点另行写入，记录通过临时文件原子替换。
- 启动恢复期间已有新任务时，合并磁盘记录与当前队列，调整冲突任务 ID 及前置识别引用，避免跳过旧任务或覆盖新任务。配置锁定时在侧栏与队列提示解锁后恢复。
- 修正序列化替换器读取条目引用的方式，处理 `Zotero.Item.toJSON()` 先于替换器执行的行为。已有错误记录按条目 key 重新取得运行时对象，覆盖来源、结果附件与一键整理子任务；恢复记录缺少文献库 ID 时仅接受唯一匹配。
- 恢复记录包含任务设置、来源条目、云端任务 ID、切片状态、已完成译段和流程步骤。条目通过文献库 ID 与条目 key 重新加载，识别所需的临时输入保存在本机任务目录。
- 更新卸载时暂停请求，等待正在保存的结果写入，再保存队列。新版启动或 Zotero 重启后，配置解锁即可恢复未完成任务。
- MinerU 恢复原批次并核对未确认上传。Marker／Datalab 复用已返回的任务 ID。PaddleOCR 保存各切片的任务 ID 和已取得的结果。
- 全文翻译复用已完成片段。一键整理跳过已完成步骤，大纲生成复用同一次任务中已完成的分块。已生成但尚待保存的总结、书目信息和标题译文也会记录。
- 原先等待用户决策的任务恢复为暂停状态。异步提交结果尚未确认时，提示用户核对服务端任务后重试。

### 升级注意事项

首次安装任务恢复功能前，请先保存或完成旧版本中的任务。自动恢复依赖启用此功能后建立的恢复记录。恢复记录保存在本机，执行恢复任务前需要解锁配置。

## 文档并发调度

| 服务 | 默认文档并发 | 可设置范围 |
| --- | --- | --- |
| MinerU | 2 | 1–10 |
| PaddleOCR | 2 | 1–10 |
| Marker | 2 | 1–10 |
| MarkItDown | 2 | 1–10 |

- 各服务设置页增加独立的并发控制，适用于官方和自部署接口。同一服务接口的普通识别和一键整理任务共享文档名额。MinerU 与 PaddleOCR 的双引擎调用也使用对应的文档名额限制。
- MinerU、PaddleOCR、Marker 和 MarkItDown 在识别及双引擎核对完成后释放文档调度名额，后续保存、总结和翻译可与下一份文档识别重叠。同一文献的任务仍互斥。
- MarkItDown 按服务地址共享识别和一键整理名额。官方未公布固定最大并发数，实际吞吐取决于服务端进程配置和资源。
- PaddleOCR 按接口地址管理文档名额，排队任务可以取消，任务失败后释放名额。
- 上述设置控制 OCRFlow 客户端的任务调度，实际同时处理数量由云端调度或自部署服务配置决定。

## 所有支持格式均可生成 HTML

- 移除 EPUB、Office、网页、文本及部分图片格式强制只保存 Markdown 的限制。所有已支持格式均遵守“同时生成 HTML”选项。
- 生成 HTML 时保留配套 Markdown 和图片资源，供阅读、总结和全文翻译使用。
- 保留原文布局与 Markdown 布局选项。识别结果缺少版面坐标时，原文布局按可用的文档结构排版。
- EPUB 分批转换后合并为一份完整 HTML 和配套 Markdown。保存失败后的重试复用已完成的转换结果。

## 队列与设置界面

- 任务队列增加“定位条目”，切回文库并选中任务对应条目或附件。重试、终止、复制、定位条目按两列两行排列，云端进度查询使用独立一行。

- 分别显示云端排队、等待识别名额、翻译待处理和实际处理状态，队列汇总使用对应的显示状态。
- MinerU 云端排队显示等待时长。队列与侧栏增加“查询云端进度”，读取已有批次并刷新切片状态，查询错误单独显示。
- 手动查询取得完成结果后可接续下载。自动与手动查询同时返回完成状态时，共享一次结果下载和提取。
- 修复设置页说明文字占用表单列引起的标签、输入框错位，收窄数字框并左对齐复选框。页面适配 Zotero 默认设置窗口的可用宽度。
- PDF 默认服务明确区分官方与自部署接口，并将旧配置映射到原来的接口选择。移除设置页任务队列中的手动查询本地 MinerU 任务入口。

## 兼容性修复

- MinerU 自部署根据 `/v1/health` 的 `features.task_output_formats` 选择 4.1 Tasks 协议或旧版 Jobs 协议。4.1 使用 JSON `POST /v1/tasks`、`file_name/bytes`、`output_formats=["default"]`，按回执的上传地址执行 PUT，使用逐文件 `result_url` 下载 ZIP。
- 新接口采用 `GET /v1/tasks/{task_id}` 查询与 `POST /v1/tasks/{task_id}/cancel` 取消，保留代理路径前缀。任务 ID、文件 ID 与成功上传标记写入恢复记录，覆盖双引擎的两个识别来源。已完成任务可直接下载结果，查询错误不会自动创建任务，成功 PUT 不因等待确认而重复上传。
- 任务创建请求等待服务端回执，以便终止操作取得任务 ID 后继续取消。上传与下载只向同源 API 附加插件配置的 Bearer 凭据，外部签名地址使用返回的链接与请求头。
- 协议依据 [MinerU 4.1 Tasks 文档](https://github.com/opendatalab/MinerU/blob/master/docs/en/usage/tasks.md) 与 [迁移说明](https://github.com/opendatalab/MinerU/blob/master/docs/en/reference/migration_4_1.md)。

- EPUB 转换结果中，感叹号紧邻章节或脚注链接形成的伪图片语法会还原为标点和普通链接。常规转换与 HTTP 413 后分批转换均执行此处理，保留实际图片的缺失检查。

- 修复英文日期中的 `$^{st}$` 等序数上标被当作公式占位符、导致自然中文译文未通过结构校验的问题。批量与单段重试统一规范日期输入，保留公式、脚注标记和现有已完成译段。

- 为 pdf-lib 的独立加载环境提供日志接口，将解析警告接入 Zotero 日志，修复部分 PDF 读取时出现的 `console is not defined`。
- 修复 Marker／Datalab 已完成识别但大纲缺少逐页文字的问题，可从已保存的文档结构恢复页码来源。
- 修复 MinerU 入口丢弃调用方 `cloudState` 的问题，切片状态可以用于任务恢复和手动进度查询。
- “识别后继续生成大纲”清除旧错误，并在前置识别失败时提示重试。

## 验证

418 项插件测试通过，覆盖任务恢复、配置解锁、保存阶段更新、并发上限、识别完成后的名额释放、取消与失败释放、手动云端查询，以及全部已支持非 PDF 格式的 HTML 输出、保存重试和 EPUB 脚注链接处理。

实际服务联调（MinerU 4.2.2 Router）：使用合成 HTML 通过插件入口完成创建任务、上传、轮询与逐文件 ZIP 下载，核验 ZIP 中 Markdown 标题和正文；另创建未上传的测试任务，确认取消接口返回 canceled。此项联调覆盖 Flash 原生文档流程，PDF 模型推理尚未实测。
