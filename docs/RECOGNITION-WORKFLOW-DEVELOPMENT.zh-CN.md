## 1. 范围与实施原则

本轮包括：按文件类型选择默认识别服务、MinerU 新格式及解析选项、长 PDF 切片与多文档批量解析、页级来源展示与大纲恢复、一键整理顺序及附件重命名、同文献操作排队、网页快照仅生成 Markdown、侧栏更新提示，以及加密配置备份的本机命名和数量管理。

保留已有加密配置、中英文界面、双引擎校勘、逐段对照翻译和任务重试能力。优先扩展现有模块，不引入新的服务端、任务平台或通用引擎框架。本文不要求新增用量区域、推荐奖励链接、图片语义分析或服务部署。

用户已授权按本文开发，版本更新为 1.5.6，先不推送 GitHub。用户已确认命名、切片上传调度、备份清理范围及更新提示规则；确认结果见第 13 节。

## 3. 默认服务设置与格式路由

### 3.1 设置布局

设置 → 识别服务顶部增加小标题“默认服务设置”，原“PDF / 图片识别服务”改为“PDF识别服务”，下面依次显示：

1. PDF识别服务。
2. Office文档识别服务。
3. HTML识别服务。
4. 图片识别服务。

候选服务仅显示插件已经适配、且对应接口支持该输入的选项。服务名称后可区分云端／本地配置；沿用现有连接设置，不在默认服务区域重复填写密钥。单次操作明确指定服务时，覆盖该类型的默认值。

| 输入类别 | 计划候选 | 说明 |
| --- | --- | --- |
| PDF | MinerU、PaddleOCR、Marker、AI 视觉、MarkItDown | MarkItDown 转换不等于对扫描 PDF 做完整视觉 OCR |
| Office | MinerU、MarkItDown | MinerU 官方云端按下述格式接入；本地需已适配的接口支持 |
| HTML | MinerU、MarkItDown | MinerU 云端使用 `MinerU-HTML`；网页快照规则见第 8 节 |
| 图片 | MinerU、PaddleOCR、AI 视觉 | 每个来源只开放自身已适配的图片格式 |

Marker 图片直传等尚未确认并适配的组合，不因出现在其他类别就自动开放。只配置了不能处理当前输入的来源时，在上传前提示原因，不静默改用另一收费服务。

### 3.2 格式范围与配置保存

MinerU 官方云端新增 Office 和图片类型的依据见第 13 节。HTML 使用独立模型。PDF 以外不能继续无条件进入 `PDFDocument.load`。

本地 MinerU 4.0 的原生解析支持范围比旧版接口广，包含 EPUB；但不能仅依据项目版本说明，就假定用户部署的 HTTP 服务已经开放同样能力。本轮只开放实际完成适配的组合。EPUB 保留现有 MarkItDown 路径；本地 MinerU EPUB 在完成对应接口验证后再开放，不新增独立 EPUB 默认服务下拉框。

纯文本、Markdown 和 CSV 保留已有可直接读取的路径，不为了统一菜单而额外上传。已生成的 OCR HTML／Markdown 与原始网页快照要按来源区分。

新值通过现有 `getPref/setPref` 和加密配置保存，纳入导入、导出与同步的现有字段校验。兼容旧配置仅需简单缺省规则：PDF 沿用旧默认值；其他类型仅在旧来源确实支持时沿用，否则使用原有适配路径并提示缺失配置。不静默选用另一个云端来源，也不设计新的迁移框架。

任务入队时保存本次服务、模型、语言及解析选项。之后修改设置不改变已经入队的任务。

### 3.3 MinerU 公式与表格选项

在 MinerU 配置中增加“公式识别”“表格识别”两个复选框，默认均开启。

- 官方云端分别发送 `enable_formula`、`enable_table`。
- `vlm` 的公式开关只控制行内公式，界面用一句简短说明。
- HTML 模型下不提供无效开关，不发送不适用参数。
- 本地配置使用已适配接口的实际参数；不支持时明确显示不适用，不能只保存开关却不生效。
- 同一批次的全局解析选项必须一致。

## 4. MinerU 批量、切片与并发

### 4.1 两个不同的限制

**用户要求：默认最多同时处理 5 个原始文档；单次申请最多 50 个上传链接，超过后自动排队。**

| 对象 | 定义 | 处理规则 |
| --- | --- | --- |
| 原始文档 | 用户选择的一份附件 | 一个用户可见识别任务；切成多少份仍算一个文档 |
| 切片 | 从原 PDF 生成的页范围文件 | 独立上传、接收进度及重试，归属于原始文档 |
| 批次 | 一次申请上传链接对应的文件集合 | 最多 50 个文件；解析选项一致，可来自多个活动文档 |
| 文档并发 | 处于识别处理中的原始文档数 | 默认上限 5；其他文档保持排队 |

50 是单次申请上限，不是整个用户队列的容量。超过后生成后续批次，由调度器自动提交，无需用户再次点击，也不要求前一批所有文件完成后，才允许提交下一批。实际服务端解析并发由 MinerU 决定，界面不承诺同时启动 50 个解析工作。

此默认 5 个文档的限制用于本轮批量识别调度，不把已有总结／翻译等服务的并发一律改为 5。一个文档完成识别并保存结果后，释放识别名额，其后续一键整理阶段继续沿用现有调度。

**已确认的传输实现：**在最多 5 个活动文档之间轮转准备和上传切片；每个文档同一时刻最多有一个正在上传的切片。已上传切片可同时在服务端解析。这样长书内部可并行解析，也避免一次把 50 份大文件全部读进 Zotero 内存。该规则替代此前“总共只允许同时上传 2 个文件”的建议，不另增一组高级并发设置。

### 4.2 PDF 切片

1. 读取页数与原文件大小；不修改原始附件。
2. 未超限的 PDF 直接作为一个待上传文件。
3. 超限的 PDF 按连续页切片，每片不超过 200 页；保存后检查实际字节大小，过大则继续缩小页范围。
4. 文件大小按官方限制检查；实现可保守采用 200,000,000 字节作为本地上限，不依赖 MB／MiB 换算差异。
5. 单页自身仍超限时，明确提示无法自动切片，不反复重试，不擅自压缩原图。
6. 保存切片的原始页起止范围，返回后统一恢复页码。

不能只通过 `page_ranges` 上传一份仍超限的原 PDF 来代替真实切片。Office 转换后的页数限制由服务实际检查；本轮不开发 Word／PPT／Excel 的自动切割系统，超限需提示用户拆分或选择已有其他适配来源。

示例：520 页 PDF 切为 1–200、201–400、401–520 三片；另一份 80 页 PDF 无需切片。参数相同时，这 4 个文件可进入同一批次，但用户队列仍显示两个文档任务。

### 4.3 批次提交与结果分发

沿用官方异步上传流程：申请地址 → 上传各文件 → 服务自动解析 → 轮询批次 → 分发并保存结果。

- 同一服务地址、账号配置、模型、语言、公式／表格选项的文件才合并批次；HTML 单独分组。
- 每批按顺序维护文件与上传地址对应关系；每片分配唯一 `data_id`，关联文档任务和页范围，不使用内容哈希。
- 一次最多取 50 片。剩余切片保留在待提交队列，调度继续推进；活动文档之间轮转取片，避免一本长书占满所有提交机会。
- 一个批次只维护一个轮询工作，按 `data_id` 更新对应切片。未找到结果时继续等待或显示明确异常，禁止回退到结果数组第一项。
- 不同文档互不等待结果落盘；一份完成即可保存并继续后续流程。
- 同一长文档所有切片成功后，再按原页顺序合并为正式识别结果。
- 已成功切片及批次标识保存到现有任务恢复数据或临时结果目录；失败只重试失败片。先有恢复数据，再清理临时文件。
- 上传地址过期时，仅为尚未上传成功的文件重新申请，不自动重提已在解析的文件。
- 网络短暂中断先保留已知批次和进度；重试优先查询已有任务，不立即重复上传。

### 4.4 合并与真实进度

合并必须修正：PDF 物理页偏移、块来源片段、图片资源与引用、脚注编号及关联、大纲页级缓存。不得按返回先后顺序拼正文。

对于每片页码从 1 开始的结果：`原始物理页 = 切片物理页 + 切片起始页 - 1`。保留原始响应，不能原地改写为全书页码后丢失原始证据。

侧栏沿用智能体执行步骤样式：

```text
识别全文                         执行中
  MinerU · 官方云端
  已解析 260 / 520 页
  切片 1：第 1–200 页，已完成
  切片 2：第 201–400 页，60 / 200 页
  切片 3：第 401–520 页，服务端排队中
```

总进度累计成功片的页数和服务已回报的解析页数；不把上传成功当作解析完成。服务未回报页数时只显示实际阶段。每片成功只累计一次，重试不重复加数；非 PDF 使用服务真正提供的进度单位。

### 4.5 终止和失败

终止一个文档：停止其未开始的切片、取消本地上传／等待、忽略其后续结果写入；不取消同批其他文档。轮询仍服务其他活动文档时继续运行。

官方云端不能确认取消正在解析的工作时，提示“已停止等待，服务端可能继续处理”，不能宣称已经释放服务端算力。清楚区分本地终止与服务端取消，不沿用一个批次共用的取消信号误伤其他文献。

切片失败保留成功片，任务显示“部分切片失败，可重试”；不把不完整识别结果当作全书进入总结、翻译。完成片可用于重试恢复，但本轮不另增部分 OCR 成品导出功能。

## 5. 页码展示、跨页段落与大纲

### 5.1 每页仅显示一次来源

OCR Markdown 和 HTML 采用“横线 + PDF 第 N 页”，每个实际物理页仅一处。页码来源于真实逐页结果，不通过总字数分配，不把印刷页码当 PDF 物理页。

Markdown 示例：

```markdown
---
PDF 第 1 页

本页标题、正文、图片和注释……

---
PDF 第 2 页

下一页内容……
```

页码不是 Markdown 章节标题，不进入大纲或翻译文本。HTML 使用页级标记及横线；内层块仍保留来源信息，但不逐段重复展示页码。

跨页逻辑段落保留完整语义单元，并在原页界保留来源锚点。渲染页标记不把一个段落拆成两个翻译请求。双栏译文继续按逻辑自然段对齐；跨页段落以页范围表达来源，不伪造译文字词与原页界的精确对应。表格、脚注、列表、代码围栏内不直接插入会破坏语法的横线，页界由结构来源保留并在可用块边界展示。

空白页保留真实页的位置，可简短注明未提取到正文。旧结果只有全文、缺少逐页证据时，不补造页码，提示重新识别以恢复对应关系。

PDF 使用物理页；PPT 使用幻灯片编号；Excel 使用工作表及实际定位信息；Word、网页没有可信分页时不标“PDF 第 N 页”。

### 5.2 大纲生成与恢复

页级数据是大纲可靠跳转的基础，但添加可见页码不能单独解决模型未返回目录的问题。两部分需分别实现。

取材顺序：复用可靠 OCR 页级缓存与已有 PDF 目录 → 尝试后台逐页提取 → 缺少可用文字时进入“需要处理”，提供“识别后继续生成大纲”。不为了大纲静默触发额外收费识别。

模型目录与定位规则：

- 分块保留成功结果；空返回或结构无效时建议额外重试一次，仅重试失败块。
- 仍失败且原始结构中存在可靠标题时，可生成基础大纲，并说明来源。
- 标题必须与对应页文本或可信结构匹配；不能只因为模型页码在范围内就接受。
- 阿拉伯文等真实输入的匹配可规范化附加符号、延长符和数字形式；显示标题保留原文。
- 无法定位的条目标记“未定位”，不生成错误的跳页位置。
- 没有可用目录时保留旧大纲和已完成数据，显示具体原因及可行操作。

## 6. 一键整理与重命名

### 6.1 全流程顺序

统一为：**识别 → 建条 → 补全（含重命名）→ 翻译标题 → 总结 → 全文翻译 → 大纲**。

复用已有有效全文与父条目。建条、补全根据实际缺失处理，不重复创建条目。没有 PDF 的网页／Office 等来源，在大纲阶段说明不适用并跳过阅读器 PDF 大纲。

识别失败时，依赖全文的阶段不能继续；后续总结、翻译、大纲之间可独立处理，一项失败不阻止其余有条件运行的阶段。重试仅执行失败或未完成阶段，已经成功的总结和译文不重复生成。

标题翻译读取独立配置，将原标题译文写入短标题；一键整理的补全阶段不再写入模型生成的 `shortTitle`，避免目标语言冲突。已有短标题按覆盖设置保留，失败继续后续可运行步骤，重试只补跑未完成步骤。按钮副文案保持“识别、建条、补全、总结、翻译、大纲”，不额外展示标题翻译。

### 6.2 命名规则

“正文”按原始 PDF／EPUB 等附件理解；补全条目成功后执行重命名。单独点击“补全条目”也执行相同规则。

| 文件 | 计划命名 |
| --- | --- |
| 原始附件 | `作者姓（等）_年份_题目.扩展名` |
| 识别附件 | `OCRFlow_作者姓（等）_年份_题目.md` 或 `.html` |
| 翻译附件 | `翻译OCRFlow_作者姓（等）_年份_题目.md` 或 `.html` |

其中“（等）”表示多作者时的文字规则，不是文件名中固定的括号。**已确认：**单作者用作者姓，多作者用第一作者姓加“等”；例如 `Rahal等_2021_题目.pdf`。翻译前缀直接使用“翻译OCRFlow_”，不额外插入下划线。

- 依据 Zotero 姓氏字段、当前版本出版年份和原始 `title`；不使用已翻译的 `shortTitle`。
- 单字段机构作者使用实际名称；缺少真实数据时明确使用“未知作者”“年份不详”等占位，不让模型编造。
- 同步更新文件名与附件显示标题；保留扩展名、校勘版本及部分译文后缀。
- 重名时使用现有避让机制，不覆盖文件；配套 Markdown 和图片引用继续有效。
- 原始网页快照保留其结构和内部资源路径，不按普通单文件方式改动快照内部文件。
- 任务关联使用条目 ID，不持有重命名前的旧路径。后续生成的识别／翻译文件读取补全后的命名数据。
- 重命名失败不撤销已补全元数据、不丢失文件；队列给出原因，只重试重命名。

## 7. 同文献操作可以排队

有正在执行的任务不再是禁用按钮的理由。侧栏、右键菜单和批量入口使用相同规则。

例：文档正在识别时，用户仍可依次点击总结、翻译、大纲，进入队列；当前操作完成后依序检查前提并执行。同一父条目的文件写入与元数据修改继续串行，不为“可点击”而并发覆盖同一结果。

- 有正在生成的全文／父条目作为前置条件时，允许入队，显示等待原因。
- 执行前重新解析父条目、附件和实际可用全文；原文件入口使用当时有效的关联结果。用户明确选择某份 Markdown／HTML 时保留该选择。
- 前置识别失败时，后续任务进入“等待前置条件”并释放执行名额，不保持假运行；重试识别成功后自动重新检查。
- 同文献同操作重复点击，若参数和所选来源相同，定位已有排队／运行任务；明确选择了不同模型或服务的任务可分别排队。
- 真正不适用的操作仍禁用并说明原因，例如独立笔记不能凭空生成 PDF 大纲；标题翻译继续只依赖已有父条目的原题名。
- 不同文献依照现有服务／模型规则并发，不被某篇文献的等待前置条件卡住。

这里只增加现有任务所需的前置条件与来源解析，不开发通用工作流编排器。

## 8. 网页快照与书内图片

### 8.1 网页快照

抓取的网页快照转为 Markdown，**不再生成另一份 HTML 成品附件**，即使全局开启“同时生成 HTML”。原始 Zotero 快照保留；服务原始响应可作为内部原始数据保留，不作为第二份可见 HTML 成品。

读取保存的快照内容，不擅自改成重新抓取实时网页。转换保留可提取的图片、链接、表格、来源网址及已有条目元数据。快照的本地资源需在上传前正确处理；无法访问的资源不能按本机相对路径让云端读取。后续总结／翻译使用所生成 Markdown。

### 8.2 书内图片

保留识别服务返回的图片、图注和所在页，正确保存引用；服务提供的图中文字也保留。图片文件可被解析，不代表书内每幅照片、地图的所有细节都已做文字识别或语义解释。

本轮不默认逐图再调用一次 AI，不以模型描述替换原图。此前讨论的“对插图额外识别文字”仅作为后续可选能力，不计入本轮验收。

## 9. 右侧栏更新概括

### 9.1 位置和内容

放在 OCRFlow 顶栏下方、“当前选中文献”上方。淡黄色背景、细边框和适度留白；深色模式使用低亮度黄色并保持文字可读。沿用现有字体和按钮样式，不新增弹窗。

显示当前插件版本和 2–4 条简短更新概括；底部提供“关闭”“不再提醒”。内容随插件打包，提供中英文，跟随现有语言设置，不在线下载公告。

示意内容仅说明最终版式，发布时替换为实际完成的变化：

```text
OCRFlow · 本次更新
• 支持按文件类型设置默认识别服务
• 支持长文档切片与批量识别
• 优化页码标记和任务排队

关闭                         不再提醒
```

### 9.2 已确认的显示规则

- 更新后第一次打开侧栏时展示；切换文献不重置显示状态。
- “关闭”：仅关闭当前版本的提示；重启、切换文献或同版重装均不再显示该版本，更新至其他版本时可再次提醒。
- “不再提醒”：屏蔽当前首位版本号下的后续更新提示。例如在 1.5.2 点击后，1.5.3、1.6.0 及其他 1.x.x 更新均不提醒；升级至 2.0.0 时仍提醒。
- 大版本按版本号首位判断，1.x.x → 2.x.x 属于大版本变化；第二位或第三位变化不解除“不再提醒”。在新的大版本中，用户可以再次选择“不再提醒”。
- 本机分别保存已关闭的具体版本和已屏蔽的大版本号，不能只用一个布尔值实现两个按钮。首次安装可记录当前版本为基线，不冒充更新。
- 状态按本机保存，不参与用户配置的导出和官方同步，避免另一台机器替用户关闭提示。
- 未知旧版基线时建议显示一次当前版概括；无选中文献时也可以关闭提示。

上述按钮语义和大版本边界已由用户确认；不增加第三个按钮或另一套公告设置。

## 10. 加密配置备份：本机名与保留数量

### 10.1 设置入口

在设置 → 同步功能的加密配置管理区域增加两个字段，沿用现有设置样式：

| 字段 | 规则 |
| --- | --- |
| 本机名 | 用户自行填写，例如“办公室 Mac”“家用电脑”；用于备份文件名和同步来源显示 |
| 每台机器最多保留备份数 | 正整数，默认 10；至少保留 1 份 |

本机名和保留数量属于当前机器的设置。导入或应用另一台机器的配置时，保留本机值，不把远端机器名覆盖到本机。建议未填写本机名时使用可读取的系统设备名；取不到时显示“本机”，不阻止原有导出和同步功能。

### 10.2 文件命名与来源归属

新备份、手动导出的默认文件名、通过 Zotero 同步生成的配置附件，均包含生成机器的本机名和生成时间，例如：

```text
OCRFlow_办公室Mac_20261027-153000_<现有记录ID>.ocrflow-config
```

- 使用文件名可用的本机名，替换路径分隔符等不允许字符；设置页保留用户填写的显示名。
- 时间与现有记录 ID 用于区分同名／同秒生成的配置，不覆盖已有备份，不新增内容哈希。
- 同步附件的显示标题包含来源机器和时间，方便在远端版本列表中区分。
- 用户仍可在手动导出时自行改名；改名不改变包内来源信息。
- 每台安装保留一个本机设备标识，备份记录携带该标识与生成时的本机名。设备标识用于计数，本机名只用于显示；两台电脑同名也分别保留 10 份，修改本机名也不重新获得 10 个历史名额。
- 沿用现有记录 ID 进行同步去重，不能在文件改名后仍只依赖旧的 `<记录ID>.ocrflow-config` 文件名判断是否已发布。
- 配置正文和密钥继续加密保存；不因文件名加入本机名而改为明文配置。

### 10.3 自动清理范围

用户要求为每台机器默认保留 10 份，超过自动清理。**已确认清理范围：**插件管理的本地自动备份和 Zotero 同步历史分别执行这一上限；手动导出到用户自选目录的文件只提供命名，不扫描或删除。

清理按生成机器的设备标识分组，按备份生成时间保留最新 N 份，优先清理最旧历史。正在使用的本地配置文件不计入备份数。

1. 新备份写入成功后再清理，不能先删除旧备份再尝试创建新文件。
2. 同步配置附件成功创建后，再清理本机生成且超过上限的旧附件；本机创建成功不代表 Zotero 云端已上传完成。
3. 同步历史通过 Zotero 原有条目删除流程移入废纸篓，由原生同步传播删除；不直接删除同步附件的底层文件，不自动清空废纸篓。上限按有效历史条目计数。
4. 只清理当前机器生成的历史，不因调低本机上限而删除另一台机器的备份；另一台机器在自己生成备份时执行自己的保留规则。
5. 改小上限并保存后，对本机已管理的历史执行一次清理；改大上限不会恢复已删除历史。只编辑输入框时不清理。
6. 清理失败不撤销已保存的配置及新备份，显示简短原因，下一次生成备份时继续尝试。
7. 旧版没有设备归属的备份／同步记录继续可读取，不根据模糊的文件名猜机器来源后自动删除；默认不计入某台机器的新保留名额。

本轮不增加定时备份、新的备份目录选择或远程清理服务。继续在已有导入／应用配置前创建本地备份，按原有同步时机生成同步配置；普通设置保存不因此额外新增一份自动备份。

### 10.4 现有实现改造

- `config.js`：将固定的 `.backup` 扩展为受管理的带机器名历史备份；在已有记录中补充生成机器信息；同步发布按记录身份去重并在成功后执行保留规则。
- `config-preferences.js`、`preferences.xhtml`：增加本机名与数量字段、默认导出名、同步来源显示和保存反馈。
- 本机身份不随配置导入或应用远端版本替换；来源信息随对应备份保留，不将同步中的其他设备记录误认为本机。
- 更新加密配置使用说明和中英文文案，写清自动清理范围、旧备份密码规则，以及手动导出不受自动清理影响。

| 1.5.2 点击“关闭”后换文献、重启、同版重装，再更新至 1.5.3 | 1.5.2 不再提示；1.5.3 可显示新的更新概括 |
| 1.5.2 点击“不再提醒”，再更新至 1.5.3、1.6.0、2.0.0 | 两个 1.x.x 版本均不提醒；2.0.0 恢复显示更新提示 |
| 填写本机名，备份／导出／生成同步配置 | 文件默认名包含本机名和生成时间，内容仍加密，同步来源可区分 |
| 同一机器连续生成 11 份受管理备份，上限为 10 | 新备份保存成功后，最旧历史被清理，剩余最新 10 份；当前配置不受影响 |
| 两台机器同名、本机改名、导入远端配置 | 按设备来源分别计数，本机名不被远端替换，改名不重置保留数量 |

| 有其他机器历史、旧版无归属记录和手动导出文件 | 自动清理只处理当前机器受管理历史，不误删其他文件 |
| 同步附件改为带机器名后再次发布同一配置记录 | 按现有记录 ID 去重，不重复创建同步附件 |
| 中文／英文、浅色／深色、窄侧栏 | 文案正确、按钮可点击，文本不溢出或覆盖 |

每个检查对应上述具体失败；修正文档本身只需检查 Markdown 链接、需求覆盖和修改范围，不为纯文档改动运行模型测试或生成新版本。
